The checkout/address form currently lacks proper validation and address verification logic. The complete form validation system needs to be improved to make the checkout process production-ready, secure, and user-friendly.

────────────────────────────
CHECKOUT FORM VALIDATION REQUIREMENTS
────────────────────────────

Currently, users are able to:

* enter text characters in mobile number fields
* enter invalid data in name fields
* manually change state/city values even after pincode-based auto-fetch
* submit incomplete or mismatched address information

This should be completely fixed with proper frontend and backend validation.

────────────────────────────
FIELD VALIDATION REQUIREMENTS
────────────────────────────

1. FULL NAME FIELD

* Allow only alphabets and valid name characters
* Prevent numbers and special characters
* Trim extra spaces automatically
* Minimum and maximum character validation
* Show proper inline validation messages

Example:
✅ “Akash Kumar”
❌ “12345”
❌ “Akash@123”

────────────────────────────

2. MOBILE NUMBER FIELD

* Allow only numeric input
* Restrict to valid Indian mobile number length (10 digits)
* Prevent alphabets and special characters
* Prevent entering more than allowed digits
* Add real-time validation while typing

Example:
✅ “9876543210”
❌ “abcd123”
❌ “99999”

────────────────────────────

3. EMAIL FIELD

* Proper email format validation
* Prevent invalid email structures
* Show instant validation feedback

Example:
✅ “[user@gmail.com](mailto:user@gmail.com)”
❌ “usergmail”
❌ “@gmail.com”

────────────────────────────

4. PINCODE VALIDATION & ADDRESS VERIFICATION
   ────────────────────────────

Currently:
When the user enters pincode “560069”, the system correctly fetches:

* state
* city
* address data

BUT:
The user can manually change the state to something incorrect like:
“Arunachal Pradesh”

This should NOT be allowed.

REQUIRED FIX:

Once the pincode data is fetched:

* state should be auto-filled and locked/read-only
* city should be auto-filled and locked/read-only
* district/location should remain synchronized with the pincode

Users should NOT be able to enter mismatched address combinations.

Example:
If pincode = 560069

Then:
✅ State = Karnataka
✅ City = Bengaluru

And user should NOT be able to change it to:
❌ Arunachal Pradesh

────────────────────────────
ADDRESS CONSISTENCY VALIDATION
────────────────────────────

Implement proper address verification logic:

* Validate pincode against state/city
* Prevent invalid combinations
* Show error messages for mismatched locations
* Ensure database consistency before order placement

If the user changes the pincode:

* automatically refresh the related state/city fields
* clear outdated address data
* refetch the correct location details

────────────────────────────
USER EXPERIENCE REQUIREMENTS
────────────────────────────

Validation should feel:

* smooth
* modern
* premium
* non-intrusive

Include:

* real-time validation
* inline error messages
* red border highlights for invalid fields
* success indicators for valid fields
* disabled checkout button until all validations pass
* smooth validation animations/transitions

────────────────────────────
SECURITY & DATA INTEGRITY
────────────────────────────

Validation must happen on BOTH:

1. Frontend
2. Backend

Do NOT rely only on frontend validation.

Backend must:

* sanitize inputs
* validate all fields again before saving orders
* reject invalid/mismatched address submissions
* prevent tampered requests

The checkout flow should be production-ready and ensure users cannot place orders using invalid or inconsistent address information.
