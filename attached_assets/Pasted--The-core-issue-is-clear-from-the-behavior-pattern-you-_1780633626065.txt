🐛 Root Cause Explanation (for Replit)

The bug is in how the texture/material is composed when a print is active.

What's happening internally:

For Pattern t-shirts, color likely works by modifying a shader uniform or tinting a procedural material — so color changes instantly update the visible mesh.

For Printed & Solid t-shirts, the color is probably stored in state but the 3D material/texture is NOT being recomposed and reapplied to the mesh after a color change. The reset button works because it clears the print texture, which forces a full material rebuild — and that rebuild picks up the saved color.

✅ Tell Replit to fix it with this exact logic:

Every time color OR print changes, the material must be fully recomposed and re-applied to the mesh. There should be one single function like updateMaterial() that:

function updateMaterial() {
  1. Start with the base color (selected garment color as a canvas/texture tint)
  2. IF a print is selected:
       - Create a new canvas/texture
       - Fill background with the selected color
       - Draw/composite the print image ON TOP of that color
       - Apply the composed texture to the 3D mesh material
  3. IF no print is selected:
       - Apply the selected color directly to the mesh material (solid color)
  4. Call material.needsUpdate = true  (Three.js) 
     OR force a re-render of the mesh
}

The bug is that when a print is active on the t-shirt and the user changes the garment color, setColor() updates the state but does not recompose or reapply the material to the 3D mesh. The color only appears after Reset because Reset triggers a full material rebuild that reads the saved color.

This is why patterns work (they use a shader/tint approach that reacts to color state directly) but printed/solid shirts don't (they use a canvas/texture compose approach that only runs when the print changes, not when color changes).
