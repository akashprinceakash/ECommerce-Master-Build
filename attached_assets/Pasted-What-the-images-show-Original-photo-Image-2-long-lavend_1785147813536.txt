The common thread across both models: whichever garment is processed against an already-synthetic image, rather than the real photo, is the one that loses fidelity. Reordering top-vs-bottom doesn't eliminate this — it just decides which garment eats the risk.

FASHN's own team has acknowledged this exact category of problem still needs work: Supporting the simultaneous fitting of two clothing items (e.g., a top and a bottom) isn't in our immediate plans. However, feature (4) of the virtual try-on model roadmap will greatly improve the ability to fit items consecutively while preserving the details of the first item. — meaning even FASHN doesn't currently claim consecutive-garment chaining is fully solved.

Two paths forward, from here:

A — Quick test, no code change (do this first): Manually reverse it once — run shorts first against your original photo, then polo second against that result. If the polo then comes out wrong instead of the shorts, that confirms definitively it's a "whatever's second degrades" problem, not something specific to bottoms. Cheap to test (2 API credits), and tells us for certain whether reordering-per-outfit is a viable permanent strategy (e.g., always process whichever garment is historically more failure-prone — bottoms — first, so it gets the clean photo).

B — The structural fix, if A confirms the pattern: Stop chaining entirely. Run both garments as independent single-garment generations against the same original photo, then composite the two results together programmatically (crop the top half from result A, the bottom half from result B, blend at the waistline using sharp). Neither generation ever sees a synthetic image — both get the real photo — so this class of bug can't occur at all. This is real, additional engineering work (image compositing, finding a reliable waist-crop line across arbitrary photos/poses), but it's the only approach that structurally eliminates the problem rather than working around it.
