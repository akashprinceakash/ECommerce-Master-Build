Client identified a major cart/authentication UX issue that needs to be fixed properly across the ecommerce flow.

━━━━━━━━━━━━━━━━━━━

1. ADD TO CART SHOULD WORK WITHOUT FORCED LOGIN
   ━━━━━━━━━━━━━━━━━━━

Current behavior:

* User adds an item to cart
* Immediately receives:
  “You need to sign in first”

This creates friction in the shopping experience.

Required change:

* Users should be able to:

  * browse products
  * select size
  * add items to cart
  * continue shopping

WITHOUT being forced to log in immediately.

Authentication should only become mandatory at:

* Checkout
  OR
* Buy Now / payment stage

This is standard ecommerce UX followed by premium ecommerce platforms.

Expected behavior:

* Guest users can build their cart freely
* Login/signup prompt should appear only when proceeding to checkout/payment

━━━━━━━━━━━━━━━━━━━
2. CART ITEMS MUST PERSIST AFTER LOGIN
━━━━━━━━━━━━━━━━━━━

Current issue:

* User added item to cart
* Then login/signup flow appeared
* User logged in successfully using Google account
* After clicking “Go to Cart”
  → Cart became empty

This is a major UX and state-management issue.

Expected behavior:

* Cart items added BEFORE login must remain intact AFTER login
* Guest cart should merge with authenticated user cart automatically
* User should NEVER need to re-add products after authentication

Required implementation:

* Store guest cart locally/session-side before login
* After successful authentication:

  * merge guest cart into authenticated cart
  * sync with backend/database
  * preserve quantities, selected sizes, and product variants
