Build/fix the backend logic for KA.SHA Golfwear product customization so that the correct t-shirt design automatically loads into the 3D customizer based on the selected product SKU.

PRIMARY GOAL

When a customer visits any product page and clicks “Customize T-Shirt”, the exact selected product must automatically load into the 3D customization page before the customer makes any edits.

The 3D model should immediately show:

* correct style
* correct pattern or print
* correct color variant

No manual selection should be required.

This must be fully controlled through SKU mapping.

---

1. REQUIRED USER FLOW

---

1. Customer opens a product page.
2. Product has a unique SKU.
3. Customer clicks “Customize”.
4. Backend sends SKU to customization engine.
5. Customizer reads SKU.
6. SKU automatically determines:

   * product type
   * pattern / print / solid
   * texture asset
   * color variant
7. 3D model loads with that exact product already applied.
8. Customer can then edit colors/logo/text.

Example:

Selected product:
SKU = KS1001B-BB

On customization page:

* load Pattern 1001
* apply Blue + Black colorway
* render directly on 3D shirt

Customer edits from there.

---

2. PRODUCT TYPE DETECTION FROM SKU

---

Backend must parse SKU.

A)

PRINT SKU FORMAT

KS1000BGP001

Meaning:

* KS = Ka.Sha
* 1000 = print collection
* BGP = golf print
* 001 = print design number

Logic:

if sku starts with KS1000BGP
→ productType = print

Load print asset directly.

Example:

KS1000BGP001
→ print library design 001

KS1000BGP015
→ print library design 015

Important:
Use full print library in backend.

All print files attached must be registered.

Current total:
~34 print designs

Map example:

{
"KS1000BGP001": "/prints/KS1000BGP001.png",
"KS1000BGP002": "/prints/KS1000BGP002.png",
"KS1000BGP003": "/prints/KS1000BGP003.png"
}

Continue through all 34.

---

B)

PATTERN SKU FORMAT

KS1001B-BB

Meaning:

KS = Ka.Sha

1001 / 1002 / 1003 / 1004 / 1005
= shirt pattern style

B
= golfwear base

Suffix
= color variant

Examples:

KS1001B-BB
→ Pattern 1001
→ Blue + Black

KS1002B-RB
→ Pattern 1002
→ Red + Black

KS1003B-PB
→ Pattern 1003
→ Purple + Black

KS1004B-OB
→ Pattern 1004
→ Orange + Black

KS1005B-SB
→ Pattern 1005
→ Sky Blue + Black

Important:

REMOVE old:

* KD001
* KD002
* KD003
* KD004
* KD005

Use only:

KS1001B
KS1002B
KS1003B
KS1004B
KS1005B

Each pattern supports multiple color variants.

Example backend structure:

{
"KS1001B-BB": {
"patternId": "1001",
"baseColor": "blue",
"accentColor": "black",
"asset": "/patterns/1001.glb"
},

"KS1001B-SB": {
"patternId": "1001",
"baseColor": "skyBlue",
"accentColor": "black"
},

"KS1002B-RB": {
"patternId": "1002",
"baseColor": "red",
"accentColor": "black"
}
}

Important:

Suffix controls only colors.

Pattern number controls shirt layout.

---

C)

## SOLID SKU STRUCTURE

Create new solid SKU format.

Use:

KS1000B-XX

Examples:

KS1000B-WH
= solid white

KS1000B-BK
= solid black

KS1000B-NV
= navy

KS1000B-SB
= sky blue

KS1000B-RD
= red

KS1000B-GN
= green

Logic:

if sku starts with KS1000B-
→ productType = solid

Apply solid color to whole shirt.

Example:

{
"KS1000B-WH": {
"type": "solid",
"color": "#ffffff"
}
}

---

3. BACKEND SKU ROUTER

---

Backend route:

/customize/:sku

Examples:

/customize/KS1000BGP001

/customize/KS1001B-BB

/customize/KS1000B-WH

Flow:

receive sku

detect type

if print
→ load print texture

if pattern
→ load pattern model + color variant

if solid
→ load plain shirt + color

return config to frontend

Frontend applies immediately to 3D model.

---

4. FRONTEND 3D MODEL REQUIREMENT

---

On page load:

read SKU

fetch product config

apply:

* mesh
* texture
* material colors

before render

So customer sees exact product instantly.

Then customization tools remain enabled:

* change colors
* upload logo
* add text

State persists.

---

---

Product clicked:
KS1000BGP015

Customizer opens:
→ exact print 015 already rendered

Product clicked:
KS1002B-RB

Customizer opens:
→ pattern 1002
→ red + black already rendered

Product clicked:
KS1000B-WH

Customizer opens:
→ solid white shirt already rendered

Then customer customizes further.

Main objective:
SKU must be the single source of truth for backend + 3D configurator initialization.
